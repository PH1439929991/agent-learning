# 第十五节：多条命中补取邻居，并去重

## 1. 为什么学习这一节

前面已经能检索、组装消息和计算检索指标。但命中段可能只有一句“原因如下”，答案在下一段。这次复用第三节 expand_neighbors，把单命中的邻居扩展接到多条 hits，再去重，供消息组装使用。

这是上下文准备，不是重新生成向量，也不是更换检索模型。是否改善最终回答要另做实验，不能由代码测试通过就断言效果更好。

打开 [context_expansion.py](../../src/agent_learning/module_08_rag/context_expansion.py)，只填写 expand_context_chunks 的三个 TODO。演示纯离线，不读密钥、不调用模型、不修改 live 入口。

## 2. 输入是什么

```python
expand_context_chunks(chunks, hits, window=1)
```

- chunks：同一资料版本的全部片段，每个 chunk_id 唯一，可以乱序。
- hits：检索命中，按照相似度排名，每条包含 chunk 字典。
- window=1：同一篇文档前后各补一段；不是字符数，也不是 top_k。

演示资料 A 有四段：

```text
A_000：背景：练习角色正在选择居住地。
A_001：他最终选择住在示例地区，原因如下。
A_002：原因是当地设有图书馆，便于学习。
A_003：他也喜欢参加读书交流活动。
```

另有 B_001，属于另一篇文档，不应因为编号接近就当成 A 的邻居。

输入 hits 简化展示：

```python
[
    {"chunk": {"chunk_id": "A_001", ...}, "score": 0.9},
    {"chunk": {"chunk_id": "A_002", ...}, "score": 0.8},
]
```

省略号只用于说明，实际字典有完整正文和 metadata。

## 3. 中间结果：分别扩展

处理第一条命中 A_001，expand_neighbors 返回：

```python
[A_000的字典, A_001的字典, A_002的字典]
```

处理第二条命中 A_002，返回：

```python
[A_001的字典, A_002的字典, A_003的字典]
```

直接相加会把 A_001、A_002 放入两次，浪费上下文。

注意 expand_neighbors 的第一个参数必须是全部 chunks，不是 hits。否则未命中的前后段根本没有机会被补进来。

## 4. 用集合记住哪些 ID 已经加入

```python
selected = []     # 最终片段列表，保留完整记录和加入顺序
seen_ids = set()  # 已加入的 ID，用于快速判断重复
```

依次处理六个候选：

| 遇到的 ID | 是否已经见过 | 操作 |
| --- | --- | --- |
| A_000 | 否 | 追加完整片段，记录 ID |
| A_001 | 否 | 追加完整片段，记录 ID |
| A_002 | 否 | 追加完整片段，记录 ID |
| A_001 | 是 | 跳过 |
| A_002 | 是 | 跳过 |
| A_003 | 否 | 追加完整片段，记录 ID |

判断写法是 chunk_id not in seen_ids，记录写法是 seen_ids.add(chunk_id)。set 用 add，list 用 append。

不要直接把完整片段字典放入 set；本题用字符串 ID 做去重键。也不要只返回 ID，因为下一步组装消息还需要正文和来源。

## 5. 最终输出是什么

函数返回完整片段字典列表，ID 顺序如下：

```python
["A_000", "A_001", "A_002", "A_003"]
```

这行只展示 ID，真实返回值是对应的四个字典。

顺序采用“首次出现”规则：按 hits 排名依次处理，每次邻居按原文顺序返回，重复项不再加入。不保证最终列表全局按文档序号排序。

例如反过来先命中 A_002，再命中 A_001，会得到 A_001、A_002、A_003、A_000。这个练习明确保留首次出现顺序，未来如需按文档整体合并，要单独设计排序规则。

## 6. 如何接到消息组装

外围代码已经写好：

```python
context_hits = [{"chunk": chunk} for chunk in selected]
messages = build_rag_messages(query, context_hits)
```

第八节的 format_chunk 只读取 hit["chunk"]，不需要 score。补来的邻居不能假装拥有命中段的相似度，所以不复制或编造分数。

消息中的引用编号按新列表生成：[1] 对应 A_000，[2] 对应 A_001，[3] 对应 A_002，[4] 对应 A_003。

以后校验回答引用时，source_count 应为最终发送的 len(context_hits)=4，而不是原始 len(hits)=2。如果后面还有 Token 预算裁剪，要在裁剪后再编号并计数。

## 7. 边界与限制

- window=0 只保留命中段，并按 ID 去重。
- 文档开头、结尾只取实际存在的邻居，不补空段。
- 空 hits 返回空列表；找不到命中 ID 报错，不能悄悄跳过。
- 邻居只能来自同一 document_id；片段位置取 chunk_index，不是 chunks 列表下标。
- 不修改输入字典。本函数返回的字典与原资料共享对象，不承诺深拷贝，后续若要改元数据应先复制。
- 去重仅针对重复 ID；相邻片段中由 overlap 产生的重复文字仍然存在。
- 本节不设 Token 预算，window 越大可能带来更多无关资料，不是越大越好。
- 原始检索 Recall@K 与扩展后上下文覆盖率不是同一个指标，不把邻居冒充检索命中来抬高 Top-K 分数。
