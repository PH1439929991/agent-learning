# 第十四节：复用排名，对比不同 K

## 1. 本节目的

上一节已经能收集实际排名并计算指标，本节比较同一排名的 Top-1、Top-2、Top-3。先以最大 K 检索一次，再在本地计算各个前缀的指标。

打开 [retrieval_k_comparison.py](../../src/agent_learning/module_08_rag/retrieval_k_comparison.py)，只写 compare_top_k 的三个 TODO。默认演示与测试均为离线，不调用模型；上一节的真实评测尚未在本会话执行。

## 2. 输入长什么样

```python
cases = [
    {"case_id": "q1", "query": "练习角色住在哪里，喜欢什么？",
     "expected_chunk_ids": ["A", "B"]}
]
ks = [1, 2, 3]
```

retrieve 是另一个输入参数：接收问题和 K，返回 hits。本节演示传入 fake_retrieve；它返回手写排名 X、A、B。

## 3. 每一步得到什么

第一步，整理候选 K：

```python
unique_ks = sorted(set(ks))  # [1, 2, 3]
max_k = max(unique_ks)      # 3
```

如果传 [3, 1, 2, 3]，也会得到 [1, 2, 3]，重复 K 不需要重复评测。这里对 K 去重排序是合理的，不是在重排检索片段。

第二步，调用一次 collect_retrieval_results，以 max_k 收集每道题的排名。返回 ranked_cases：

```python
[
    {
        "case_id": "q1",
        "query": "练习角色住在哪里，喜欢什么？",
        "expected_chunk_ids": ["A", "B"],
        "retrieved_chunk_ids": ["X", "A", "B"],
    }
]
```

collect_retrieval_results 整体只调用一次；它内部会对每道题调用一次 retrieve。因此 N 道题是 N 次检索，不是整个问题集只有一次检索。

第三步，遍历 unique_ks，调用 evaluate_cases(ranked_cases, k)。单题函数会使用 retrieved_chunk_ids[:k]，不需要自己裁剪或修改原排名。

| 当前 K | 参与评分的排名 | 命中的相关片段 | 命中率 | 平均召回率 |
| --- | --- | --- | --- | --- |
| 1 | X | 无 | 0.0 | 0.0 |
| 2 | X、A | A | 1.0 | 0.5 |
| 3 | X、A、B | A、B | 1.0 | 1.0 |

只有一道题时，命中率只能是 0 或 1；多道题才可能出现 2/3 等比例。

## 4. 最终返回什么

reports 是列表，每个元素是一份完整报告。以下省略 details 内部字段，实际代码须保留：

```python
[
    {"k": 1, "case_count": 1, "hit_rate_at_k": 0.0,
     "mean_recall_at_k": 0.0, "details": [...]},
    {"k": 2, "case_count": 1, "hit_rate_at_k": 1.0,
     "mean_recall_at_k": 0.5, "details": [...]},
    {"k": 3, "case_count": 1, "hit_rate_at_k": 1.0,
     "mean_recall_at_k": 1.0, "details": [...]},
]
```

省略号只是文档占位，不是让你写进结果。直接使用 evaluate_cases 的返回值即可。

## 5. 你的三个 TODO

1. 得到 unique_ks 和 max_k。
2. 在 K 循环之外调用 collect_retrieval_results，得到 ranked_cases。
3. 在 K 循环里只计算指标，收集 reports，循环外返回。

注意别把第二步放进 K 的循环，否则相同问题会重复检索。接入上一节真实检索函数时，每题检索包含一次 Embedding；复用排名可以避免为每个 K 重复编码问题。本节尚未添加 live 入口。

## 6. 什么时候可以这样复用

当前项目使用固定向量的精确余弦排序，改变 K 只是取同一排名的不同前缀，所以适用。必须保持问题、资料版本、模型与检索策略一致。

如果检索算法、过滤或重排过程会随 K 改变，这样算出来的是固定排名前缀的对比，不一定等于分别运行那些设置的真实效果。

本节不是跨进程缓存，重启程序仍会重新调用检索函数。也不自动选“最好的 K”：更大的 K 可能带入更多无关资料和上下文开销；这几个小样本不能代表所有问题。
