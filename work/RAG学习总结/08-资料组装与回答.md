## 函数输入与输出

build_rag_messages(query, hits) 接收问题字符串和命中片段列表，返回两个消息字典。类型提示 list[dict[str, str]] 表示列表里的字典键和值为字符串，不是额外的输入参数。

- system：回答规则、依据资料、缺信息时说明、使用引用编号。
- user：问题和带编号的资料正文。

role=user 不代表所有文字都是用户手写的；程序可以把问题与资料组装成一条消息。

## enumerate 的顺序

```python
blocks = []
for source_number, hit in enumerate(hits, start=1):
    blocks.append(format_chunk(hit, source_number))
```

enumerate 固定返回“编号、元素”。第一轮 source_number=1、hit=hits[0]。变量名不会改变赋值顺序；写反后 hit 会成为整数，hit["chunk"] 就报错。

start=1 只改变计数起点，不跳过第一个元素，也不改变列表下标。编号从 1 开始方便标记 [1]、[2]。

format_chunk 的参数定义是“命中、编号”，所以调用时又是 hit 在前；调用看函数定义顺序。

## 消息组装

使用 "\n\n".join(blocks) 拼接正文。\n 表示换行，不是额外字段。

format_chunk 选取正文、英雄名、片段 ID 和来源，不把 embedding 和 score 塞入 messages。

answer_from_hits 在有命中时组装消息并调用 generate；无命中时本地返回资料不足。现有单轮 CLI 读取缓存，只编码问题，再调用聊天模型；暂未接 Agent 工具循环。
