> 学习日期：2026-09-03
> 学习范围：Function Calling、JSON 数据读取、工具 schema、工具注册表、工具执行器、多工具路由与 Agent Loop。

## 1. 阶段成果

这一阶段完成了一个可以真实运行的《英雄联盟》背景资料助手。模型不再只依靠自身知识回答，而是可以根据用户问题选择并调用本地 Python 工具。

完整流程如下：

```text
用户提出问题
  ↓
模型阅读 System Prompt 和工具 schema
  ↓
模型判断是否需要调用工具
  ↓
模型返回函数名和 JSON 参数
  ↓
程序通过工具注册表找到 Python 函数
  ↓
执行函数并读取本地英雄资料
  ↓
将工具结果作为 tool 消息返回模型
  ↓
模型整理成自然语言答案
```

本阶段主要文件：

| 文件 | 作用 |
| --- | --- |
| `champions_tools.py` | 实现查询单个英雄和列出英雄的工具函数 |
| `champion_agent.py` | 单工具 Function Calling 练习 |
| `multi_tool_agent.py` | 多工具注册、路由、执行和循环 |
| `data/champions.json` | 保存英雄详细背景资料 |
| `data/regions.json` | 按地区保存英雄索引 |

最终实现了两个工具：

```python
get_champion_info(champion_name: str) -> dict
list_champions(region: str = "") -> dict
```

## 2. Function Calling 是什么

Function Calling 并不是让模型直接执行 Python 函数。模型只负责决定：

- 是否需要调用工具；
- 调用哪个工具；
- 应该传入什么参数。

真正执行函数的是我们自己的程序。

```text
模型：建议调用 get_champion_info，并给出参数
程序：找到 get_champion_info 函数并执行
模型：根据函数执行结果组织最终回答
```

模型可能返回类似内容：

```json
{
  "name": "get_champion_info",
  "arguments": "{\"champion_name\": \"亚索\"}"
}
```

其中 `arguments` 通常是 JSON 字符串，程序需要先解析，才能作为 Python 参数使用。

## 3. JSON 文件读取

### 3.1 打开并解析 JSON

```python
with open(DATA_file_path_champions, "r") as file:
    champions = json.load(file)
```

执行过程：

```text
Path 对象定位文件
  ↓
open() 以只读方式打开文件
  ↓
json.load() 读取并解析 JSON
  ↓
返回 Python 对象
  ↓
champions 变量接收结果
```

`with` 代码块结束后，Python 会自动关闭文件，不需要手动调用 `file.close()`。

项目中的文件路径使用当前 Python 文件作为基准：

```python
DATA_file_path_champions = (
    Path(__file__).parent / "data" / "champions.json"
)
```

这样无论从哪个终端目录启动程序，都能找到正确的数据文件。

### 3.2 JSON 与 Python 类型对应关系

| JSON | Python |
| --- | --- |
| object | `dict` |
| array | `list` |
| string | `str` |
| number | `int` 或 `float` |
| `true` | `True` |
| `false` | `False` |
| `null` | `None` |

例如下面的 JSON：

```json
{
  "yasuo": {
    "name_cn": "亚索",
    "region": "艾欧尼亚",
    "related_characters": ["易", "阿狸"]
  }
}
```

经过 `json.load()` 后，可以看作下面的 Python 字典：

```python
champions = {
    "yasuo": {
        "name_cn": "亚索",
        "region": "艾欧尼亚",
        "related_characters": ["易", "阿狸"],
    }
}
```

可以使用字典语法读取：

```python
champions["yasuo"]["name_cn"]  # 亚索
```

## 4. 查询单个英雄

工具首先对用户输入进行标准化：

```python
query = champion_name.strip().lower()
```

这里包含两个字符串操作：

- `strip()`：删除字符串开头和结尾的空白；
- `lower()`：将英文字母转换成小写。

例如：

```python
"  Yasuo  ".strip().lower()  # "yasuo"
```

这样用户输入 `Yasuo`、`yasuo` 或带有首尾空格的内容，都能得到相同的查询值。

每个英雄支持使用多种名称查询：

```python
searchable_names = {
    champion_id.lower(),
    champion_data.get("name_cn", "").lower(),
    champion_data.get("name_i8n", "").lower(),
    champion_data.get("title", "").lower(),
}
```

集合中包含：

- 英雄 ID，例如 `yasuo`；
- 中文名，例如 `亚索`；
- 英文名，例如 `Yasuo`；
- 称号，例如 `疾风剑豪`。

查询成功时返回统一结构：

```python
{
    "success": True,
    "champion_Id": champion_id,
    "champion_data": champion_data,
}
```

查询失败时也明确返回业务状态：

```python
{
    "success": False,
    "message": "未找到该英雄",
}
```

## 5. 按地区列出英雄

`list_champions` 的 `region` 参数带有默认值：

```python
def list_champions(region: str = "") -> dict:
```

这表示调用者可以传地区：

```python
list_champions("艾欧尼亚")
```

也可以不传：

```python
list_champions()
```

函数需要处理三个分支：

```text
没有地区 → 汇总并返回全部英雄
地区不存在 → 返回 success=False
地区存在 → 返回该地区英雄
```

不传地区时，遍历所有地区并汇总英雄：

```python
all_champions = []

for region_data in regions.values():
    all_champions.extend(region_data.get("champions", []))
```

`regions.values()` 返回每个地区对应的数据，`extend()` 将每个地区的英雄逐个加入 `all_champions`。

需要特别区分：

```python
all_champions.append(region_champions)
```

会加入一个完整列表，容易形成嵌套列表；而：

```python
all_champions.extend(region_champions)
```

会把列表中的英雄逐个加入结果。

## 6. 工具 schema

工具 schema 是提供给模型看的“函数说明书”，并不是实际执行的 Python 函数。

```python
{
    "type": "function",
    "function": {
        "name": "get_champion_info",
        "description": "根据中文名、英文名或称号查询某个英雄的背景资料。",
        "parameters": {
            "type": "object",
            "properties": {
                "champion_name": {
                    "type": "string",
                    "description": "英雄中文名、英文名或称号。",
                }
            },
            "required": ["champion_name"],
            "additionalProperties": False,
        },
    },
}
```

各字段含义：

| 字段 | 作用 |
| --- | --- |
| `type: function` | 声明这是函数工具 |
| `name` | 模型返回的工具名称，必须与注册表一致 |
| `description` | 告诉模型工具能解决什么问题 |
| `parameters` | 描述整个参数对象 |
| `properties` | 定义每一个参数 |
| `required` | 定义必填参数 |
| `additionalProperties: False` | 不允许模型添加未声明参数 |

`parameters` 描述的是完整的参数对象，其中的 `properties` 通常与 Python 函数的参数对应。

```python
def get_champion_info(champion_name: str) -> dict:
```

对应：

```json
{
  "type": "object",
  "properties": {
    "champion_name": {
      "type": "string"
    }
  },
  "required": ["champion_name"]
}
```

`list_champions` 的 `region` 是可选参数，因此不能把它放入必填列表：

```python
"required": []
```

也可以省略 `required` 字段。

## 7. 工具注册表

模型返回的是工具名称字符串，例如：

```python
function_name = "get_champion_info"
```

字符串本身不能执行，因此需要一个注册表，将名称映射到真实函数对象：

```python
TOOL_REGISTRY = {
    "get_champion_info": get_champion_info,
    "list_champions": list_champions,
}
```

左侧是字符串，右侧是函数对象：

```text
"get_champion_info" → get_champion_info 函数
"list_champions"    → list_champions 函数
```

查找函数：

```python
function = TOOL_REGISTRY.get(function_name)
```

动态传递参数并执行：

```python
result = function(**arguments)
```

假设：

```python
arguments = {"champion_name": "亚索"}
```

那么：

```python
function(**arguments)
```

等价于：

```python
get_champion_info(champion_name="亚索")
```

## 8. 通用工具执行器

工具执行器负责连接“模型返回的工具调用”和“本地 Python 函数”。

```python
def execute_tool_call(tool_call: Any) -> dict:
    function_name = tool_call.function.name

    try:
        arguments = json.loads(tool_call.function.arguments)
    except json.JSONDecodeError as error:
        return {
            "success": False,
            "message": f"工具参数不是合法 JSON：{error}",
        }

    function = TOOL_REGISTRY.get(function_name)
    if function is None:
        return {
            "success": False,
            "message": f"未注册的工具：{function_name}",
        }

    try:
        return function(**arguments)
    except TypeError as error:
        return {
            "success": False,
            "message": f"工具参数不匹配：{error}",
        }
```

执行器依次完成：

1. 读取模型选择的函数名；
2. 将 JSON 参数字符串转换为 Python 字典；
3. 从注册表中获取函数对象；
4. 使用 `**arguments` 调用函数；
5. 将成功结果或错误信息返回给 Agent Loop。

## 9. System Prompt 的思考方法

System Prompt 不需要重复完整的工具参数 schema，但应该告诉模型行为规则。

本次采用下面的结构：

```text
角色
+ 工具使用规则
+ 回答规则
+ 数据边界
+ 缺少信息时的处理方式
```

关键规则包括：

- 查询具体英雄时调用 `get_champion_info`；
- 查询某地区或全部英雄时调用 `list_champions`；
- 普通寒暄不调用工具；
- 缺少必要信息时先请用户补充；
- 只能根据工具结果回答；
- 工具返回失败时明确说明没有查到；
- 不把原始 JSON 直接展示给用户。

System Prompt 决定“应该怎样工作”，工具 schema 描述“工具可以怎样调用”，二者职责不同但需要保持一致。

## 10. Agent Loop

一次工具调用通常需要两次模型请求。

第一次请求：

```text
用户问题 + 工具说明
→ 模型决定调用工具
```

执行工具后，将结果加入消息：

```python
messages.append(
    {
        "role": "tool",
        "tool_call_id": tool_call.id,
        "content": json.dumps(tool_result, ensure_ascii=False),
    }
)
```

这里的 `tool_call_id` 用于告诉模型：这条工具结果对应之前的哪一次调用。

第二次请求：

```text
原始问题 + assistant 工具调用 + tool 执行结果
→ 模型生成最终自然语言回答
```

核心循环：

```python
for _ in range(max_tool_rounds):
    response = client.chat.completions.create(...)
    assistant_message = response.choices[0].message
    messages.append(assistant_message)

    tool_calls = assistant_message.tool_calls or []
    if not tool_calls:
        return assistant_message.content

    for tool_call in tool_calls:
        tool_result = execute_tool_call(tool_call)
        messages.append(
            {
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": json.dumps(
                    tool_result,
                    ensure_ascii=False,
                ),
            }
        )
```

`max_tool_rounds` 用于防止模型不断请求工具而形成无限循环。

## 11. 多工具路由

当 `TOOLS` 中存在多个工具时，调用请求使用：

```python
tools=TOOLS,
tool_choice="auto",
```

`auto` 表示允许模型根据问题决定：

- 不调用工具；
- 调用 `get_champion_info`；
- 调用 `list_champions`。

路由效果：

| 用户问题 | 期望行为 |
| --- | --- |
| 亚索是谁？ | 调用 `get_champion_info` |
| 艾欧尼亚有哪些英雄？ | 调用带地区参数的 `list_champions` |
| 资料库里有多少英雄？ | 调用不带地区参数的 `list_champions` |
| 你好 | 不调用工具 |

## 13. 已遇到的典型问题

### 13.1 `function` 拼写错误

错误：

```python
"fuction": {
```

正确：

```python
"function": {
```

字典键拼错不会触发 Python 语法错误，但 API 无法把它识别为工具定义。因此只运行 `py_compile` 不够，还需要检查 schema 内容和真实请求。

### 13.2 注册了函数但没有导入

注册表写了：

```python
"list_champions": list_champions
```

但如果没有导入函数：

```python
from champions_tools import list_champions
```

模块加载时会抛出：

```text
NameError: name 'list_champions' is not defined
```

### 13.3 可选参数被声明成必填

Python 函数允许省略地区：

```python
def list_champions(region: str = "") -> dict:
```

如果 schema 又写成：

```python
"required": ["region"]
```

模型会认为地区必须提供。Python 函数签名、工具 schema 和 System Prompt 三者必须保持一致。

### 13.4 对 `None` 调用 `.get()`

下面的表达式在地区不存在时会出错：

```python
regions.get(region).get("champions", [])
```

因为第一个 `.get(region)` 可能返回 `None`，继续执行就相当于：

```python
None.get("champions", [])
```

正确做法是先检查：

```python
region_data = regions.get(region)

if region_data is None:
    return {
        "success": False,
        "message": f"未找到该地区: {region}",
    }
```

### 13.5 提示返回全部英雄，但没有返回数据

只返回一句：

```python
{"success": True, "message": "返回所有地区英雄"}
```

模型仍然不知道英雄名单。工具返回值必须真正包含完成回答所需的数据，例如：

```python
{
    "success": True,
    "region": "全部",
    "champion_count": len(all_champions),
    "champions": all_champions,
}
```

### 13.6 schema 示例与真实数据不一致

如果工具描述把“德玛西亚”列为示例，但 `regions.json` 没有这个顶级地区，模型可能根据示例发起一个注定失败的查询。

工具名称、描述、参数示例和数据范围都应该与真实能力一致。

## 15. 下一阶段

下一阶段可以在当前 Function Calling 基础上继续学习 Agent 工程化：

```text
Pydantic 参数校验
  ↓
统一工具返回模型
  ↓
超时、异常和重试
  ↓
pytest 自动化评测
  ↓
```

建议先为每个工具定义输入模型：

```python
from pydantic import BaseModel, Field


class GetChampionInfoInput(BaseModel):
    champion_name: str = Field(
        min_length=1,
        description="英雄中文名、英文名或称号",
    )
```

然后在执行真实函数前统一校验模型生成的参数，避免空字符串、参数类型错误和额外字段直接进入业务逻辑。
