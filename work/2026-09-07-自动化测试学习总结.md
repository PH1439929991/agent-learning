## 2. 一个测试的基本结构

```python
# 准备输入
tool_call = make_call("unknown_tool", {})

# 执行被测代码
result = execute_tool_call(tool_call)

# 断言：检查结果是否符合预期
assert result["success"] is False
assert "unknown_tool" in result["message"]
```

`assert` 后的条件不成立，测试就失败。工具返回失败不等于测试失败：对于未知工具，返回失败恰好是正确行为。

`make_call()` 用 `SimpleNamespace` 构造具有 `.function.name` 和 `.function.arguments` 属性的对象，模拟工具调用输入；参数字典通过 `json.dumps()` 转成 JSON 字符串，无需请求模型。

## 3. 输入参数不等于返回结果

调用 `list_champions` 时，不传地区表示查询全部英雄，正常结果包含 `success`、`region`、`champion_count` 和 `champions`，没有 `champion_data`。

```python
assert result["success"] is True
assert result["region"] == "全部"
```

这些断言可以检查查询结果，但不能证明执行器补上了默认参数，因为真实函数本身也有 `region=""` 默认值。

要验证实际传参，需要记录工具收到的参数，而不是读取 `result["champion_data"]`。

## 4. 用替身工具记录参数

```python
def test_default_region_is_empty_string(monkeypatch):
    calls = []

    def recording_tool(**arguments):
        calls.append(arguments)
        return {"success": True}

    monkeypatch.setitem(
        TOOL_REGISTRY["list_champions"], "function", recording_tool
    )

    result = execute_tool_call(make_call("list_champions", {}))

    assert result["success"] is True
    assert calls == [{"region": ""}]
```

`calls` 是记录本。定义 `recording_tool` 时不会执行函数；执行器之后调用替身，它才会把收到的参数追加到列表。

`monkeypatch` 由 pytest 根据测试函数的参数名提供，不需要自己创建。这里的 `setitem()` 三个参数依次是：要修改的字典、要修改的键、要设置的值。

效果类似于：

```python
TOOL_REGISTRY["list_champions"]["function"] = recording_tool
```

区别在于测试结束后，pytest 会自动恢复原来的工具函数。只替换 `function`，不替换 `arguments_model`，所以真实参数校验仍然执行。

这里传入 `recording_tool`，没有括号，是保存函数对象；写成 `recording_tool()` 则会立即调用并拿到返回值，不是我们需要的效果。

最终 `calls == [{"region": ""}]` 同时检查了调用次数为一次，以及收到的参数正确。校验失败的测试则用 `calls == []` 检查工具根本没有执行。

## 5. `**` 的两种作用

定义函数时，收集关键字参数为字典：

```python
def show(**arguments):
    print(arguments)

show(region="艾欧尼亚")
# 打印：{"region": "艾欧尼亚"}
```

调用函数时，将字典展开为关键字参数：

```python
params = {"region": "艾欧尼亚"}
show(**params)
# 等价于 show(region="艾欧尼亚")
```

因此执行器中的 `tool_function(**validated_arguments.model_dump())` 是展开字典；替身定义中的 `def recording_tool(**arguments)` 是收集参数。`arguments` 只是变量名，常见的名字还有 `kwargs`。

## 6. 今晚遇到的问题

- 未注册工具的文案与实际实现不一致，导致精确相等断言失败。当前需求只要求包含工具名，因此使用 `"unknown_tool" in result["message"]`。
- 把不传地区当作错误，实际上工具会返回全部英雄。
- 混淆工具输入与返回值，访问不存在的 `champion_data` 键会触发 `KeyError`。
- 保留 `pytest.skip()`，使前面的断言即使通过，整个用例仍被标记为跳过。完成练习后应删除它。
