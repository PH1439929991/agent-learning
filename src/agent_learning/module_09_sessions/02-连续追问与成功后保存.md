## 1. 本节要做什么？

把会话存储接到“一轮问答”的外层：读取历史、加入新问题、运行本轮、检查完成结果、最后保存。

这里沿用 OpenAI Docs 的手动历史传递方式：之前的消息要成为后续请求的输入，模型不会自动读取 Python 存储器。[官方 Conversation state 指南](https://developers.openai.com/api/docs/guides/conversation-state)

“只有成功才保存”是本练习选择的应用策略，不是 API 强制要求。失败信息以后可以写入单独日志，本节不把失败的半轮消息加入已完成对话历史。

## 2. 先区分四个参数

- session_id：本次属于哪个会话，例如 "A"。
- question：本轮新问题。
- store：上一节的 SessionStore 对象，要跨多轮复用，不能每次新建。
- run_turn：执行一轮问答的函数，由程序传入。

run_turn 跟你之前学的 retrieve 一样，是回调。但它们的职责不同：retrieve 只检索；run_turn 执行一整轮问答，里面以后可以有多次模型请求和工具调用。

本节先用假 run_turn，它按预设内容返回，不联网。这是在验证消息是否正确传递和保存，不是验证真实模型是否理解代词。

## 3. run_turn 的输入和输出

输入：完整历史 + 当前 user 问题组成的消息列表。

输出：在上述列表后追加本轮消息得到的完整列表，最后一条必须是 assistant 的非空文本答案。

```python
# 输入示意，第一轮有两条：
[
    {"role": "system", "content": "只根据工具资料回答问题。"},
    {"role": "user", "content": "练习角色的旅伴叫什么？"},
]

# 输出示意，第一轮工具问答完成后有五条：
[
    system消息,
    user问题,
    assistant工具调用,
    tool资料结果,
    assistant最终答案,
]
```

以上是消息结构示意，不是可直接运行的完整 Python 数据。具体字典见 make_demo_history()。

注意：第八章 run_agent_once 返回的是报告字典，里面的 messages 尚未追加最终回答。因此不能直接把它当作本节的 run_turn；本节先确立回调约定，真实适配另做，不修改第八章。

## 4. 三个 TODO

### TODO 1：准备请求

调用 store.load(session_id)，用 request_messages 接收。若为空，先加入 system；然后加入本轮 user 问题。

此时不要 save。拿到的本来就是工作副本，改它不会影响已保存历史。

### TODO 2：执行并检查

```python
completed_messages = run_turn(deepcopy(request_messages))
validate_completed_turn(request_messages, completed_messages)
```

为什么这里又 deepcopy？因为 run_turn 可能直接修改它接收到的列表。我们要留下本轮原始请求作为比较基准，确认返回结果没有改写或删除旧消息。

检查函数已经写好：返回值必须是消息列表，保留原始请求，而且末尾是新的非空 assistant 最终答案。中间工具配对的完整协议检查留到下一节，不把本节的结构检查当成全面校验。

### TODO 3：成功后保存并返回答案

调用 store.save(session_id, completed_messages)，保存完整历史；最后返回 completed_messages[-1]["content"]。

不需要再追加一次 user，也不要只保存最后的答案。

如果 run_turn 或校验函数抛出异常，Python 就不会继续执行后面的 save。先保持这种直接向上传播的方式，不要用 except 把错误伪装成答案，也不要在 finally 里保存。

## 5. 运行后应该看到什么？

第一轮：

- 输入：“练习角色的旅伴叫什么？”
- run_turn 收到 2 条消息：system + user。
- 预设回答：“根据学习资料，旅伴是小星。[demo_000]”
- 保存 5 条：包含工具调用和资料结果。

第二轮，同一个会话 A：

- 输入：“那它来自哪里？”
- run_turn 收到 6 条消息：旧的 5 条 + 新 user。
- 预设回答：“根据学习资料，小星来自示例地区。[demo_000]”
- 保存 7 条；system 没有重复。

第三轮模拟失败：

- 输入：“继续介绍”。
- 假执行器在工作副本里写入半成品，然后抛出 RuntimeError。
- 不调用 save；A 仍保留之前的 7 条完整消息，与失败前完全相同。
- 会话 B 仍是 []。

注意：这只是不提交历史，不是撤销外部行为。如果工具已经发送邮件、写入数据库或产生接口费用，它们不会因为不保存 messages 而自动取消。
