# 第三节 A：工具调用与结果要配齐

上一节已完成读取历史、执行本轮、成功后保存。本节先实现独立检查器；通过后再接到保存前，并学习按完整轮次裁剪。不改动你已完成的会话代码。

## 1. 先看错误

正常记录是：assistant 发起 call_A，接着 tool 返回 call_A 的结果，再由 assistant 回答。

如果裁剪时只删掉发起调用的 assistant，留下 tool，下一轮就会带着“没人发起的工具结果”。反过来，只留下调用、不留下结果，也不完整。仅仅检查最后一条是 assistant 无法发现这些问题。

OpenAI 的 Chat Completions 示例用 `tool_call_id` 对应发起调用的 `id`，并把调用与结果都追加进消息列表。[官方 Function calling 指南](https://developers.openai.com/api/docs/guides/function-calling)

本练习采用同步工具消息块规则：一批调用后，收齐其全部 tool 结果，才允许下一条非 tool 消息。不涉及异步工具或其他 API 的消息结构。

## 2. 输入与输出

你只实现 [tool_message_pairs.py](tool_message_pairs.py) 中 `validate_tool_pairs(messages)` 的三个 TODO。

- 输入：完整消息列表，元素为字典；不是 SDK 对象。
- 正常输出：`None`，表示检查通过，不是 `True`，也不生成回答。
- 异常输出：抛出 `ValueError`，让调用方停止保存或发送这些不完整的消息。
- 不修改传入的列表、字典。

这只是配对检查器，不是完整 API 参数校验器。不检查工具名、参数 JSON、资料真假、最终答案，也不禁止不同批次重用 ID；同一批内的 ID 必须不同。

## 3. 中间状态是什么？

`pending_ids = set()` 是“已经发起但还没收到结果”的 ID 集合。空集合要写 `set()`，`{}` 是空字典。

| 正在处理的消息 | 处理后的 pending_ids |
| --- | --- |
| system、user | `set()` |
| assistant 同时发起 A、B | `{"A", "B"}` |
| tool 返回 B | `{"A"}` |
| tool 返回 A | `set()` |
| assistant 最终回答 | `set()` |

集合无顺序；结果 B 先返回没有问题，关键是 ID 对应。不要用“调用数量等于结果数量”代替 ID 检查：发起 A、返回 B，数量相同但配错了。

## 4. 三个 TODO

1. 看到调用：检查 ID 在这一批里是否重复，然后 `add` 到集合。
2. 看到结果：检查 ID 是否在待办中，然后 `remove`。不在说明结果孤立、配错或重复。
3. 全部消息处理完：集合仍非空就报缺少结果；为空则正常结束。

骨架已提供“结果未齐时禁止插入非 tool 消息”的检查，以及基本类型检查。写完时删除相应的 `raise NotImplementedError(...)`。

注意：`{"success": false}` 也是工具结果！业务失败不等于消息配对失败。本函数只看 ID，不分析 content。
